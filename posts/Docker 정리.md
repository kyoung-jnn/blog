한대의 서버를 하나의 용도로 사용했다.
→ 남는 서버 공간은 그대로 방치..! 비효율적이다
- **하이퍼 바이저** 기반의 가상화 출현..!

# 도커 등장
- 기존 하이퍼 바이저를 이용한 VM은 **게스트 OS**를 필요해서 무거웠다!
![](458d98fb-1.png)
- 완전 동일한 환경에서 동일한 버전의 프로그램을 각기 받기 어렵다
	- 도커 환경에는 프로그램 실행에 필요한 세팅이 이미 되어있기 때문에 간편하다!
- 다양항 프로그램, 실행 환경을 컨테이너로 추상화(패키징)하고 인터페이스를 제공하여 프로그램의 배포, 관리, 복제를 단순하게 해준다.
> 💡 **컨테이너를 사용하여 응용프로그램을 더 쉽게 만들고 쉽게 실행 할 수 있도록 설계된 도구,
> 격리된 환경내에서 애플리케이션을 배치하는 방법**
## 이미지
---
- 응용 프로그램을 실행하는 모든 것을 갖고있다. `명령어 + 스냅샷`
→ 의존성 신경쓰지 않고 가져다가 쓰면 된다! **도커 엔진이 이미지를 실행하면 (****`런타임에`****) 컨테이너가 된다.**
> 💡 ** 리눅스,윈도우,맥에 상관없이 컨테이너가 독립적이게 실행되고 격리된 환경에서 동일하게 실행된다.**

## DockerFile
---
![](458d98fb-5.png)
**시작시 실행 될 명령어 + 파일 스냅샷** 으로 구성 됌.
1. 파일 스냅 샷이 컨테이너 하드 디스크에 적재됌
2. 명령어가 실행되어서 커널을 통해서 `1.` 에서 적재한 파일에 접근
![](458d98fb-6.png)
> 💡 이미지는 **레이어**로 구성되어 있다. 해당 레이어 별로 다시 Dockerfile를 실행할 때, 동일한 레이어면 이전 **이미지의 레이어 캐시**를 재사용한다.
```docker
# 베이스 이미지 (주로 알파인)
FROM node:16-alpine AS base

# multi stage 빌드
# deps 단계
FROM base AS deps

RUN apk add --no-cache libc6-compat 
# cd 명령어
WORKDIR /app
COPY ../package.json ../yarn.lock ./
RUN yarn

# builder 단계
FROM base AS builder

WORKDIR /app
COPY --from=deps /app/node_modules ./node_modules
COPY ../ ./
RUN yarn build:dev

# runner 단계
FROM base AS runner

WORKDIR /app
COPY --from=builder /app/public ./public
COPY --from=builder /app/.next/standalone ./
COPY --from=builder /app/.next/static ./.next/static

# 포트 매핑
EXPOSE 3000

# 컨테이너를 시작할 때 실행할 명렁어, 무조건 Dockerfile에서 한번!
CMD ["node", "server.js"]
```
### ADD & COPY 차이
- **둘다 호스트에 존재하는 파일을 옮기는건 동일하다.**
그러나!, `ADD`는 압축파일을 옮길 때, 압축이 풀려서 이동한다. 그리고 url로 접속해서 파일을 다운하고 옮길 수 도있다.

## docker 기본 명령어
---
### `docker ps`
현재 실행되고 있는 컨테이너 리스트
### `docker stop & docker kill`
### **`docker rm ‘docker ps -a -q’`**
컨테이너 다 삭제
### `docker system prune`
이미지, 컨테이너 싹 삭제 (**실행 중 인 것에는 영향 X**)
### `docker run ‘이미지 이름’`
이미지를 컨테이너화 하고 실행하기
- `-p` 포트 연결을 해준다. **컨테이너 외부 \| 내부 네트워크과 연결시키기 위해**
### `docker exec ‘container id’ 명령어`
컨테이너 안에 명령어를 전달하기
- `-it` 해당 옵션 사용시 명령어 전달 후 컨테이너 터미널에 접근이 가능!
- 명령어에 `sh`** **입력시 쉘 스크립트 바로 실행 가능!! 꽤 유용 
### `docker build .`
![](458d98fb-8.png)
**Dockerfile**을 사용해서 이미지를 컨테이너를 빌드(생성)한다.
- 베이스 이미지에서 종속성이 추가 될 떄는 임시 컨테이너를 생성 후 (스냅샷 + 명령어 적재 후) 
임시 컨테이너를 토대로 **새로운 이미지**를 생성한다.
- **`-t`** **이미지의 이름을 지정해줄수있다. (Tag)**
# docker compose
---
다중 컨테니어 도커 애플리케이션을 정의하고 실행하는 도구
### `docker compose up` vs `docker compose up --build` 
**—build**는 이미지가 있든 없든 무조건 빌드한다.
## `-f`
이름 다른 도커 컴포즈 파일 사용을 위해
## `-up`
서비스 컨테이너를 생성하고 실행한다.
## `-d`
컨테이너를 생성하고 실행할 때, **백드라운드**로 실행함.
이 옵션을 넣지 않으면 실행한 콘솔 창에서 실행됌.
